Project Context: UMBC Vending Inventory System

Project Overview
The UMBC Vending Inventory System is a software prototype designed to digitize and automate inventory tracking for a legacy campus vending machine. Currently, the machine accepts Campus Card (CBORD) payments but provides no digital insights, forcing staff to rely on manual checks. This system solves that by ingesting CBORD transaction logs and automatically tracking stock levels and expiration dates in real-time without requiring hardware modifications.

Core Business Logic
Because the legacy machine's transaction logs only record the amount charged (not the specific item sold), the system relies on a Price-to-Item Mapping algorithm. Every item slot is assigned a unique price. When a transaction is ingested via CSV mock data, the backend matches the transaction amount to the unique price to deduce which slot was purchased, decrementing the inventory accordingly.

Tech Stack & Architecture
The project uses a three-tier architecture pattern:

    Frontend: A React.js Single-Page Application (SPA) serving as an administrative dashboard.

    Backend: A Python Flask middleware application that handles CSV parsing, business logic, and API requests.

    Database: A serverless SQLite database managed via the SQLAlchemy ORM.

Key Features

    Interactive Dashboard: Displays a grid of vending slots using real-time color-coding (Green, Yellow, Red) to indicate healthy stock, low stock, or approaching expiration dates.

    Automated Tracking: Parses simulated CBORD CSV transaction streams to log sales and auto-decrement inventory.

    Admin Management: Provides a web interface for student workers to input manual restocking events and update expiration dates.

    Alerting System: Generates notifications for items nearing critical stock levels or expiration.

    ==Sequence Diagram Pseudo-Code==

    PARTICIPANTS:
        Student, CBORD_System, TransactionProcessor, SlotMapper, VendingMachine, InventoryItem, NotificationService, SQLite, Frontend

    SEQUENCE FLOW:
    1. Student -> CBORD_System: purchase_item()
    2. CBORD_System -> TransactionProcessor: post_transaction_log(csv_data)
    3. TransactionProcessor -> SlotMapper: get_item_by_price(amount)
    
    ALT [Mapping Process]
        IF Mapping Error:
        TransactionProcessor -> TransactionProcessor: log_error("Unknown Price")
        ELSE Mapping Success:
        SlotMapper -> TransactionProcessor: return item_object
        TransactionProcessor -> VendingMachine: process_sale(transaction_data)
        VendingMachine -> SQLite: decrement_stock(slot_id)
        SQLite -> VendingMachine: return updated_record
        VendingMachine -> InventoryItem: refresh_status()
        InventoryItem -> InventoryItem: check_qty_and_expiry()
        InventoryItem -> VendingMachine: return current_color (Red/Yellow/Green)
        VendingMachine -> Frontend: socket.emit('update', slot_id, current_color)
        Frontend -> Frontend: UI updates slot to Red, Yellow, or Green
        
        ALT [Alert Evaluation]
            IF current_color == "Red":
            VendingMachine -> NotificationService: send_critical_alert(item_name)
            ELSE IF current_color == "Yellow":
            VendingMachine -> NotificationService: send_warning_alert(item_name)
        END ALT
        
        VendingMachine -> TransactionProcessor: return sale_processed
    END ALT

    4. TransactionProcessor -> CBORD_System: transaction_acknowledged
    5. CBORD_System -> Student: purchase_confirmed

==ItemSlot Schema==
Attribute,Data Type & Size,Description,Constraints
Slot_ID,VARCHAR(5),"Unique identifier for the slot (e.g., ""A0"").","Primary Key, Unique"
Item_Name,VARCHAR(50),Name of the product currently in the slot.,Not Null
Quantity,INT (4 bytes),Current stock count for the slot (range: 0–10).,"Not Null, ≥ 0"
Price,FLOAT (8 bytes),"Unique price assigned to the slot (e.g., 2.15) and referenced as a foreign key by the Transaction table.","Unique, Not Null"
Exp_Date,DATE (3 bytes),Expiration date of the current batch of items in the slot.,Not Null
Days_Until,INT (4 bytes),Derived attribute. Calculated as Exp_Date minus the current system date. Not stored in the database.,N/A (Calculated)

==Transaction Schema==
Attribute,Data Type & Size,Description,Constraints
Trans_ID,INT (4 bytes),"Unique identifier for the sale, sourced from the CBORD transaction log.",Primary Key
Total_Amt,FLOAT (8 bytes),CBORD records the purchase amount. Used to identify the purchased slot via ItemSlot.Price.,"Foreign Key (ItemSlot.Price), Not Null"
User_ID,VARCHAR(20),The student or faculty ID associated with the transaction.,Not Null
Date/Time,DATETIME (8 bytes),"The date and time the purchase occurred, as recorded in the CBORD log.",Not Null

==Notification Schema==
Attribute,Data Type & Size,Description,Constraints
Note_ID,INT (4 bytes),Unique identifier for the alert record.,Primary Key
Slot_ID,VARCHAR(5),The slot that triggered the alert. Links back to the source slot.,"Foreign Key (ItemSlot.Slot_ID), Not Null"
Message,VARCHAR(100),"Text content of the alert (e.g., ""Slot B2 is low on stock"").",Not Null
Timestamp,DATETIME (8 bytes),The date and time at which the system triggered the alert.,Not Null
