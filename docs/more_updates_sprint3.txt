The sales report currently does not include the Slot ID for each item 
sold. Update the sales report generation pipeline so that every item 
in the report is mapped to its correct Slot ID using the vending 
machine's unique price-to-slot mapping strategy.

The unique price mapping strategy works as follows: every item in the 
vending machine has a unique Vending Price. When a transaction is 
recorded, the Tran Amt field uniquely identifies which item was sold. 
By matching Tran Amt against the known price list, the system can 
determine both the item name and the Slot ID of the item sold.

─────────────────────────────────────────
STEP 1 — Build the price-to-slot map in the backend
─────────────────────────────────────────

File: backend/app/utils/report_generator.py
(or wherever GET /api/reports/sales aggregates transaction data)

Before aggregating transactions, build a price-to-slot lookup 
dictionary from the current inventory. Query all ItemSlot records 
from the database and create a mapping of price → { slot_id, 
item_name }:

  price_map = {}
  slots = db.session.query(ItemSlot).all()
  for slot in slots:
    price_key = round(float(slot.price), 2)
    price_map[price_key] = {
      "slot_id": slot.slot_id,
      "item_name": slot.item_name
    }

When iterating over Transaction records to build the report, resolve 
each transaction's Slot ID by matching its tran_amt against 
price_map:

  price_key = round(float(transaction.tran_amt), 2)
  match = price_map.get(price_key)

  if match:
    slot_id = match["slot_id"]
    item_name = match["item_name"]
  else:
    slot_id = "Unknown"
    item_name = f"Unknown (${transaction.tran_amt})"

Use slot_id and item_name as the group key when aggregating 
units sold and revenue per item.

─────────────────────────────────────────
STEP 2 — Include slot_id in the API response
─────────────────────────────────────────

File: backend/app/routes/reports.py
(or wherever the GET /api/reports/sales response is built)

Ensure each item in the "items" array of the response includes 
a slot_id field. The response shape for each item must be:

  {
    "rank": 1,
    "slot_id": "A1",
    "item_name": "Bic Comfort Pens",
    "units_sold": 8,
    "total_revenue": 68.00,
    "avg_price": 8.50
  }

Ensure the top_item object in the response also includes slot_id:

  {
    "slot_id": "A1",
    "item_name": "Bic Comfort Pens",
    "units": 8,
    "revenue": 68.00
  }

─────────────────────────────────────────
STEP 3 — Update the frontend price-to-slot fallback map
─────────────────────────────────────────

File: frontend/src/utils/generateSalesReport.js

The frontend builds the report HTML from the GET /api/reports/sales 
response. Since slot_id is now included in the API response for each 
item, the frontend no longer needs to derive it. Update the table row 
builder to read slot_id directly from each item object:

  const tableRows = data.items.map((item, i) => `
    <tr>
      <td>${item.rank}</td>
      <td>${item.slot_id}</td>
      <td>${item.item_name}</td>
      <td>${item.units_sold}</td>
      <td class="revenue-cell">$${item.total_revenue.toFixed(2)}</td>
      <td>$${item.avg_price.toFixed(2)}</td>
    </tr>
  `).join("");

Update the top-selling item callout to read slot_id from 
data.top_item directly:

  const topItem = data.top_item;
  // Use in callout:
  `${topItem.item_name} (Slot ${topItem.slot_id})`

Remove any existing frontend-side price-to-slot mapping logic 
that attempts to derive slot_id from a hardcoded items array or 
from transaction amounts. The slot_id now comes exclusively from 
the API response.

─────────────────────────────────────────
STEP 4 — Handle unresolved transactions in the report
─────────────────────────────────────────

File: backend/app/utils/report_generator.py

If a transaction's tran_amt does not match any current slot price, 
the item may have been repriced since the transaction was recorded. 
In this case:
  - Do not silently discard the transaction
  - Group it under slot_id = "Unknown" and 
    item_name = "Unresolved (${tran_amt})"
  - Include it in the ranked table so the administrator can see it
  - Do not include "Unknown" items in the top_item calculation

Add an "unresolved_count" field to the API response:
  "unresolved_count": 2

─────────────────────────────────────────
STEP 5 — Display unresolved transactions in the report window
─────────────────────────────────────────

File: frontend/src/utils/generateSalesReport.js

If data.unresolved_count is greater than 0, add a visible warning 
block in the report HTML between the summary cards and the top-item 
callout:

  ${data.unresolved_count > 0 ? `
  <div class="unresolved-warning">
    ⚠ ${data.unresolved_count} transaction(s) could not be matched 
    to a current item price and are listed as Unresolved in the 
    table below. This may occur if an item's price was changed after 
    the transaction was recorded.
  </div>` : ""}

Add this CSS inside the report HTML string:

  .unresolved-warning {
    background: #fff8e1;
    border-left: 4px solid #f0a500;
    padding: 10px 14px;
    font-size: 0.82rem;
    color: #555;
    margin-bottom: 20px;
  }

Acceptance criteria:
- GET /api/reports/sales includes slot_id in every item object
- GET /api/reports/sales includes slot_id in the top_item object
- Slot ID is resolved by matching tran_amt against the current 
  inventory price list using round(float, 2) comparison
- Grid purchases include slot_id in the logged transaction record
- Uploaded CBORD transactions are resolved to slot_id via price 
  matching
- The sales report table shows the correct Slot ID for every 
  matched item
- The top-selling item callout shows the correct Slot ID
- Transactions that cannot be price-matched appear as "Unresolved" 
  in the table with slot_id = "Unknown"
- An unresolved_count field is present in the API response
- If unresolved_count > 0, a yellow warning block appears in the 
  report window
- No frontend-side slot ID derivation logic exists — slot_id comes 
  exclusively from the API response
- round(float(tran_amt), 2) is used for all price comparisons to 
  avoid floating point mismatch errors
