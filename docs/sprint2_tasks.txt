BACKEND: Phase 1 -- Domain Models & Database Layer
------------------------------------------------------------

[TASK B-1] Restructure the backend into an OOP package layout.
  Create the following subdirectories inside backend/app/:
    - models/          (SQLAlchemy ORM class definitions)
    - repositories/    (database CRUD and query logic)
    - services/        (business logic and domain operations)
    - api/             (Flask route/blueprint definitions)
    - utils/           (CSV parsing, date helpers, validators)
  Move server.py to backend/app/ entry point and register blueprints there.

[TASK B-2] Implement the ItemSlot SQLAlchemy model (models/item_slot.py).
  Fields: slot_id (PK, VARCHAR), item_name, quantity (INT), price (FLOAT, unique),
          expiration_date (DATE), low_threshold (INT, default=3), warning_threshold (INT, default=5).
  Methods:
    - decrement_stock(count: int) -> None    [raises ValueError if result < 0]
    - restock(amount: int, expiration_date)  -> None
    - days_until_expiration() -> int         [derived, calculated from today's date]
    - status_color() -> str                  [returns "Red", "Yellow", or "Green"]
    - is_critical() -> bool                  [quantity <= low_threshold OR days_until_expiration <= 2]
    - is_warning() -> bool                   [quantity <= warning_threshold OR days_until_expiration <= 5]
    - to_dict() -> dict                      [serializes all fields + derived days_until_expiration + status]

[TASK B-3] Implement the Transaction SQLAlchemy model (models/transaction.py).
  Fields: transaction_id (PK, INT), amount (FLOAT), timestamp (DATETIME),
          user_id (VARCHAR), resolved_slot_id (FK -> ItemSlot, nullable).

[TASK B-4] Implement the Notification SQLAlchemy model (models/notification.py).
  Fields: notification_id (PK, INT), slot_id (FK -> ItemSlot), message (VARCHAR),
          alert_level (VARCHAR: "warning" | "critical"), date_triggered (DATETIME).

[TASK B-5] Seed the database with realistic test data (utils/seed.py).
  Populate at least 10 ItemSlot rows with unique prices, varied quantities,
  and a mix of expiration dates (some near or past expiry) to validate all status colors.

BACKEND: Phase 2 -- Repository Layer
------------------------------------------------------------

[TASK B-6] Implement ItemSlotRepository (repositories/item_slot_repository.py).
  Methods:
    - get_all() -> List[ItemSlot]
    - get_by_id(slot_id: str) -> ItemSlot | None
    - get_by_price(price: float) -> ItemSlot | None    [used by MappingService]
    - save(slot: ItemSlot) -> None

[TASK B-7] Implement TransactionRepository (repositories/transaction_repository.py).
  Methods:
    - save(transaction: Transaction) -> None
    - get_all() -> List[Transaction]
    - get_unresolved() -> List[Transaction]            [resolved_slot_id is NULL]

BACKEND: Phase 3 -- Service Layer (Business Logic)
------------------------------------------------------------

[TASK B-8] Implement MappingService (services/mapping_service.py).
  Methods:
    - resolve_slot_by_amount(amount: float) -> ItemSlot   [raises LookupError if no match]
    - has_price_collision() -> bool                       [validates all prices are unique at startup]
  Rules: match on exact price; log an error and raise on no-match or duplicate price.

[TASK B-9] Implement InventoryService (services/inventory_service.py).
  Methods:
    - get_inventory() -> List[dict]
        Returns to_dict() for all slots.
    - restock_slot(slot_id, quantity_added, expiration_date) -> dict
        Validates inputs, saves changes, returns updated slot dict.
    - apply_sale(transaction: Transaction) -> dict
        Resolves slot via MappingService, decrements stock, persists, returns updated slot.
  Rules: wrap each mutation in a DB transaction; reject negative quantities and past expiration dates.

[TASK B-10] Implement AlertService (services/alert_service.py).
  Methods:
    - get_active_alerts() -> List[dict]
  Each alert dict must include: slot_id, item_name, quantity, days_until_expiration,
  alert_level ("warning" | "critical"), reason (e.g., "Low stock" or "Near expiration").

[TASK B-11] Implement TransactionProcessor (services/transaction_processor.py).
  Methods:
    - parse_csv(filepath: str) -> List[dict]          [reads CSV rows into raw dicts]
    - process_transactions(rows: List[dict]) -> dict  [calls InventoryService.apply_sale per row]
  Returns a summary: { processed_count, updated_slots, unresolved_amounts }.
  Unresolved amounts (no matching slot price) must be logged, not silently dropped.

BACKEND: Phase 4 -- API Routes
------------------------------------------------------------

[TASK B-12] Implement GET /api/inventory (api/inventory_routes.py).
  Returns a JSON array of all slots via InventoryService.get_inventory().
  Each object includes: slot_id, item_name, quantity, price, expiration_date,
                        days_until_expiration, status ("Red" | "Yellow" | "Green").

[TASK B-13] Implement POST /api/restock (api/inventory_routes.py).
  Request body: { slot_id, quantity_added, expiration_date }.
  Validation: slot_id exists, quantity_added > 0, expiration_date is a valid future date.
  On success: returns updated slot dict + { "message": "Restock successful" }.
  On failure: returns 400 with a descriptive error message.

[TASK B-14] Implement GET /api/alerts (api/alerts_routes.py).
  Returns only slots in warning or critical state via AlertService.get_active_alerts().
  Response includes alert_level and reason fields for each entry.

[TASK B-15] Implement POST /api/transactions/process (api/transaction_routes.py).
  Accepts a CSV file upload or a JSON list of mock transaction rows.
  Delegates to TransactionProcessor and returns the processing summary dict.

[TASK B-16] Enable CORS and standardize API error responses (api/__init__.py).
  Register Flask-CORS using the flask-cors package already in requirements.txt.
  Define a consistent error response format: { "error": "<message>", "status": <code> }.
  Apply this format to all 400/404/500 responses across all blueprints.
